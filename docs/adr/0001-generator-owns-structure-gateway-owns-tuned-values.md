# 生成器只拥有结构，现场调过的数以网关为准

给别人家配自动化时，规则由模板参数化生成（`mgs generate`），但**阈值、关灯延时这类
现场会反复调的数不属于生成器**：本地已有该规则的图时沿用图里的当前值，
只有新建的区才用 `home.yaml` 里的初值。

这和 `mgs deploy` 已有的第二条不变量是同一条道理 —— 「永不覆盖已存在变量的值，
因为变量里混着运行时状态」。阈值和延时同样混着运行时状态：看板允许住户改阈值
（`POST /api/threshold` → `rule node update`），而看板跑在住户的 Mac 上、
仓库在我这，那些改动**只存在于网关上**。若生成器以 yaml 为唯一真源，
每次重新生成都会把住户和现场调试的结果静默冲回初值，而且要先 `mgs pull`
才能在 diff 里看见自己冲掉了什么。

## Consequences

- `home.yaml` 里的 `lux` / `delay` 语义是**初值**，不是当前值 —— 字段名和文档都要这么写，
  不然下一个人会以为改了 yaml 就能改阈值（改不了，得在看板上改或者直接改图）。
- 重新生成前应当先 `mgs pull`：本地图越旧，「沿用图里的值」沿用到的就是越旧的值。
- 生成的 diff 里只会出现结构变化，这正是想要的 —— 结构变化才是需要 review 的东西。
