# 给新一户配置：现场作业单

一次上门跑完。全程要在**他家的局域网内** —— 中枢只在局域网里应答。

术语见 [CONTEXT.md](../CONTEXT.md)，设计与取舍见
[设计文档](superpowers/specs/2026-09-07-home-generator-design.md) 和 `docs/adr/`。

---

## 〇、进门前

让房主先准备好：

- [ ] **极客版已经开了**。米家 App → 中枢网关 → 中枢功能 → 自动化极客版
- [ ] **旧的普通米家自动化都关掉**。跟新规则冲突的那些会打架 ——
      1302 当初就有三条旧自动化在跟感应开灯抢，表现是「灯亮了马上又灭」
- [ ] 知道自己那台电脑是 **Mac 还是 Windows**（决定打哪个包）
- [ ] 一张户型图，手机拍的就行

你自己带上：网线或确认能连他家 WiFi。

---

## 一、勘查

```bash
mgs init                      # 第一次用才需要，生成 mgs.json
# 在 mgs.json 里加这户的网关（mDNS 实例名优先，IP 当 fallback）
xgg login --code <6位码>       # 码在米家 App 的极客版页面上，几分钟过期
mgs pull   <户>                # 有旧规则的话先拉回来看看
mgs survey <户>                # 设备清单 + 逐台 spec → data/<户>/devices.json
```

`devices.json` 是生成器的地基：**必须按目标设备的真实范围写 deviceOutput**。
1302 的吊灯色温只收 3000–6400，别家的灯可能是 2700–6500，光换 did 不换范围是错的。

## 二、走一圈，写 home.toml

这是唯一真正需要人的一步。**区是按「灯一起亮灭」划的，不是按传感器** ——
一个存在传感器覆盖沙发和餐桌、但灯分两组，那就是两个区共用一个 `sensor`。

每个区要问清楚四件事：

| 问什么 | 写进 |
|---|---|
| 哪个传感器管这块 | `sensor` |
| 感应到人要开哪几盏 | `lights` |
| 没人了要关哪几盏（常常更多，包括手动开的） | `offLights` |
| 这个区的灯归哪几个墙壁开关键管 | `switches`（决定手动锁挂几个触发） |

还有一个容易漏的：**「本区灯已灭」看哪盏**（`proxy`）。默认是 `lights` 里第一个，
但 1302 的进门区用的是吊灯而不是灯带 —— 挑那盏「这个区亮着时它一定亮」的。

照抄一份现成的开头：

```toml
prefix = "20260907"          # 今天的日期，之后永不改

[[zone]]
name   = "客厅"               # 住户叫法，进看板
rule   = "沙发"               # 规则里叫什么，可省
key    = "shaFa"              # ASCII 短名，机器拿它拼变量名
sensor = "blt.3.xxx"          # 沙发人体存在
lights = ["group.xxx"]
offLights = ["group.xxx", "yyy"]
switches  = ["2157621828:3"]  # 客厅墙开关 键2
lux    = 150                  # 初值，之后以图里的为准
delay  = "2min"               # 初值
at     = [2, 1]               # 平面图第 2 行第 1 列

[house]
hub        = "1212484402"     # 中枢网关，虚拟事件从这儿来
manualLock = true
lightOff   = true
guestMode  = { zones = ["shaFa", "canTing"] }
allLights   = [...]           # 全屋开灯/关灯/参数同步的目标
guestLights = [...]           # 会客灯要开的
```

能推的都推，配置里只写例外：总开关默认每个区都有（`master = false` 才退出）、
手动锁由 `switches` 有没有推、场景闸门由 `[[scene]] zone` 推、会客由 `guestMode.zones` 推。
拿 1302 验过：七个区的闸门链跟手建的完全一致，整份配置只写了两行例外。

## 三、生成

```bash
mgs generate <户> --out /tmp/gen    # 先看看生成什么样，不动真文件
mgs generate <户>                   # 确认没问题再写进 data/<户>/graph/
mgs lint <户>                       # 用看板的眼睛看一遍
git diff                            # 逐条看清楚
```

每条生成完立刻 `xgg rule validate --body` 离线校验，一条不过就一条都不落盘。

`mgs lint` 会把「名字里带开灯但没被当成区」的规则列出来 —— 多半是漏了照度判定。

---

## 四、部署

```bash
mgs deploy <户> --dry-run     # 先看清单
mgs deploy <户>               # 建/改
mgs enable <户> on <规则id>...  # 启用（deploy 永不改启用状态）
```

**deploy 永不改启用状态、永不覆盖已存在变量的值、不给 `--prune` 就绝不删。**

## 五、装看板

```bash
# Mac
tools/build-app.sh --arch arm64 --config data/<户>/dashboard.json
# Windows
tools/build-win.sh --config data/<户>/dashboard.json
```

`--config` 可以不给：看板会从规则图现推房间和卡片，装上打开就能用。
给了只是把显示名、平面图位置、话术一起装进去。

住户那边：

- **Mac**：解压 → 拖进「应用程序」→ 双击 → 第一次「系统设置 → 隐私与安全性 →
  仍要打开」
- **Windows**：解压 → 双击「模式看板.cmd」→ 第一次「更多信息 → 仍要运行」

页面上填中枢地址和一次 6 位登录码，地址会记住。

## 六、当场验收

逐个区走一遍，每个区确认三件事：

- [ ] 走进去灯亮，参数对（白天用全局亮度/色温，晚上用夜灯的）
- [ ] 站着不动别灭（1302 是每 60 秒重评估一次，1301 靠传感器自己续）
- [ ] 走出去等延时之后灭

再验两件全局的：

- [ ] 动一下墙壁开关 → 看板上那个区的手动锁亮起来 → 感应不再抢
- [ ] 在看板上翻一个模式 → 对应的区状态跟着变

看板上「受阻」那句话就是排查路径 —— 它会直接说是哪道闸门挡的。

---

## 七、交付

告诉住户三件事，别的都不用说：

1. **平时不用管。** 看板是出问题时才看的。
2. **「为什么这里不亮」** → 打开看板，橙色的那块会写明白是哪道闸门挡的。
3. **地址会变。** 路由器重启后连不上了，在同一个页面上改地址就行。

然后：

- [ ] 把说明书（`docs/homeowner-guide.html` 那种）发给他
- [ ] 告诉他下次上门做什么：**攒几天日志再标定照度阈值**

## 回家之后

阈值不能在配置当天定 —— 要的是「灯灭时的环境照度」，得攒样本。
几天后：

```bash
bash scripts/lux-history.sh <户> > data/<户>/lux-history-<日期>.json
```

然后改 `home.toml` 里的 `lux`……**不对**，那是初值，改了不生效（见 ADR-0001）。
阈值要么在看板上直接改，要么改 `data/<户>/graph/` 里的图再 deploy。

以后他改自动化：`mgs pull` → 改 `home.toml` → `mgs generate` → `git diff` →
`mgs deploy`。看板不用重装 —— 它每次刷新都从规则图现推。
